Workwayz User Manual & Role-Based Operational Guide

Enterprise AI-Powered Project & Portfolio Management Platform — featuring Consolidated Lifecycle Navigation, Two-Tier Bug/Escaped Defect Architecture, Multi-Tier AI & WayFinder Agent (201 Tools), and Zero-Config Local or Cloud Deployment.

1. Setup Wizard

When opening the Workwayz application for the first time (or launching the Setup Wizard at /setup-wizard), a guided 5-step wizard configures your database engine, authentication provider, master Super Admin user account, and generative AI integration.

1.1 Database Setup

Configure your primary database connection. Workwayz supports zero-configuration local storage as well as cloud/containerized databases:

  • Project Name: An identifier label for this database connection profile (e.g., Local Workspace DB or Production DB).
  • Database Provider: Supports Local Embedded Database (Built-in / Zero-Config stored in ~/.workwayz), Supabase (cloud or self-hosted Docker), and Firebase (Firestore).
  • Credentials: When Local Embedded Database is selected, no external URL or API key is required. When Firebase or Supabase is selected, enter the Project ID / URL and API / Publishable Key from your provider console.
  • Actions: Click Next → to proceed to Authentication Setup.
Figure 1.1 — Setup Wizard Step 1: Database Setup🔍 Click to expand

1.2 Authentication Setup

Configure how users authenticate when signing into Workwayz. The Authentication Provider automatically aligns with your selected Database Provider:

  • Authentication Provider: Supports Local Built-in Auth (hashes and stores credentials locally with zero external setup), Supabase Auth, and Firebase Auth.
  • Single Sign-On (SSO): Optional toggles to Enable Google SSO and Enable GitHub SSO.
Figure 1.2 — Setup Wizard Step 2: Authentication Setup🔍 Click to expand

1.3 Super Admin User Creation

Establish or reconnect the master Super Admin account for the Workwayz instance:

  • Create New Super Admin: Enter First Name, Last Name, Email ID, Password, and Re-enter Password to provision a fresh master Super Admin account.
  • Use Existing Credentials: If reconnecting to an existing database after reinstallation, toggle to "Use Existing Credentials" to verify and link your existing Super Admin account without resetting data.
  • Role & Project Assignment Rules: The first user created is assigned the Super Admin role with full access across all modules and settings. This account cannot be deleted from the UI. Note that Super Admin and Administrator accounts act strictly as system/portfolio administrators and cannot be assigned to projects as team resources or Project Managers.
Figure 1.3 — Setup Wizard Step 3: Super Admin User Setup🔍 Click to expand

1.4 AI Configuration Setup

Connect a generative AI provider to power WayFinder AI, automated stack/horizontal recommendations, AI estimation, backlog generation, test case generation, and RAID analysis. The core application runs without AI if you check "Configure AI Later".

  • Project Name: Identifier for the AI configuration profile.
  • AI Provider: Supports Google Gemini, OpenAI (ChatGPT), Anthropic (Claude), Ollama (Local), and LM Studio (Local).
  • API Key / Base URL & Default Model Override: Enter your provider API key (or local endpoint URL) and optional model override.
Figure 1.4 — Setup Wizard Step 4: AI Configuration Setup🔍 Click to expand

1.5 Finish Setup

Review the configuration summary (Database, Authentication, Admin Account, and AI Integration) and click Complete Setup to persist the profiles and launch the Workwayz login screen.

Figure 1.5 — Setup Wizard Step 5: Finish & Summary Review🔍 Click to expand

2. Signup, Login & Account Management

Workwayz provides a unified authentication portal with role-aware session management, mandatory first-login password updates for admin-created accounts, and self-service registration with administrator approval gating.

2.1 Login Portal (Home)

Opening the root URL (/) or /login presents the Workwayz login screen.

  • Credentials: Enter your registered Email and Password.
  • Remember Me: Check "Remember me on this computer" to persist your session across browser restarts.
  • Admin-Provisioned Users: When an Administrator creates a user directly from the User List, the default password is set to "P@ssw0rd". On first login, the user is automatically prompted to set a new password.
Figure 2.1 — Workwayz Login Portal🔍 Click to expand

2.2 Self-Service Signup

New users can register an account by clicking "Sign up" on the login screen /signup.

  • Required Fields: First Name, Last Name, Emp ID, Phone, Experience (years), Email, and Password.
  • Enablement Gate: Newly registered users are placed in a pending state and restricted to the My Projects screen until an Administrator enables their account and assigns an Access Level under Users → User List.
Figure 2.2 — Create an Account (Signup Screen)🔍 Click to expand

2.3 First-Login Password Reset & Pending Enablement

To enforce security and access governance during onboarding, Workwayz intercepts sessions that require action before granting workspace access:

  • Reset Your Password: Displayed immediately when logging in with the default "P@ssw0rd" credential. Requires a new password (minimum 6 characters, different from default).
  • Account Pending Enablement: Displayed on My Projects when a self-registered user logs in prior to administrator approval.
Figure 2.3a — Mandatory First-Login Password Reset Screen🔍 Click to expand
Figure 2.3b — Account Pending Enablement Screen🔍 Click to expand

2.4 Profile & Account Settings

Every authenticated user can click their profile card in the bottom-left sidebar footer and select "Profile & Account" /my-account to update their First Name, Last Name, profile avatar image, or account password.

Displays cards for all active projects and initial estimations to which the logged-in user is assigned (either as Project Manager or as a staffed project resource). Clicking a project card navigates directly to the user’s permitted landing page for that project.

Allows team members to log daily work hours across all projects they are staffed on from a single weekly timesheet grid. Users can select a project, pick a work item (Story, Sub-Task, Bug, Meeting, or Other), enter daily hours across the week, and save or submit their timesheet.

5. Initial Estimation Flow

When a new project is created with the status set to "Initial Estimation", Workwayz opens the Initial Estimation workspace. Here, Project Managers and Architects define the project summary, select or generate impacted technology systems and horizontal practices, and compute ballpark effort and cost estimates.

5.1 Specifications, Stack Suggest & Impacted Systems

In the Initial Estimation → Specifications page /projects/[id]/initial-estimation/specifications:

  • Project Summary: Enter a detailed overview of the project goals, functional scope, and target architecture, then click Save.
  • Stack Suggest (AI) / Add System: Click "Stack Suggest" to let AI recommend 3 tailored technology stacks based on the Project Summary, or click "Add System" to manually add Impacted Systems. Enter the Daily Billing Rate (USD) for each system.
Figure 5.1 — Initial Estimation: Project Summary & Impacted Systems🔍 Click to expand

5.2 Horizontals, AI Estimator & Confirming Estimation

Below Impacted Systems, configure the supporting Horizontal practices (Project Management, Business Analysis, Quality Analysis, Solution Architecture, UI/UX, DevOps):

  • Horizontal Suggest (AI) / Add Horizontal: Use AI to recommend horizontal weightage percentages or configure weightages and daily billing rates manually.
  • AI Estimator: Click "AI Estimator" to automatically calculate benchmark man-day efforts across all Impacted Systems and Horizontals based on project scope. Adjust values as needed for your team’s velocity.
  • Confirm Estimation: Click "Confirm Estimation" to baseline the estimate and transition the project into active delivery.
Figure 5.2 — Initial Estimation: Horizontals, AI Estimator & Confirm Estimation🔍 Click to expand

6.7 Development — Product Backlog, Add Requirement & Escaped Defects /development/backlog

Central repository for Epics and Product Backlog Items (PBIs). Clicking the "Add Requirement" button opens the "Add New Requirement" dialog supporting seven distinct PBI types:

  • PBI Types under Add Requirement: User Story (US-*), Feature Change (FC-*), Task (TASK-*), Enabler (EN-*), Tech Debt (TD-*), Spike (SPK-*), and Defect (Escaped Defect, DEF-*).
  • Two-Tier Bug vs. Escaped Defect Taxonomy: Production or post-acceptance escaped defects are logged here as "Defect" (itemType: "Escaped Defect", ID prefix DEF-*). Because the original story’s sprint has already closed, an Escaped Defect is estimated, assigned to an Epic, and prioritized into an upcoming sprint as a standalone PBI without reopening closed historical stories.
  • Elaboration Flow & AI Assistance: Product Owners/BAs create requirements under Epics; Tech Leads tag Impacted Systems; Developers break items into Sub-Tasks. Includes "AI Req Gen" and inline AI Sub-Task/Test Case generation.

6.12 Testing — Test Cases, Test Cycles & Test Executions

Following the natural QA execution sequence in the Testing sidebar (Test Cases → Test Cycles → Test Executions):

  • Test Cases /testing/test-cases: Master test case repository with AI Test Case Generator ("AI TC Gen") and manual creation.

  • Test Executions /testing/test-execution: Interactive test execution workspace featuring a day-by-day queue, built-in execution timer (Start/Pause/Stop), status selector (Not Run, Passed, Failed, Blocked, Skipped), actual effort logging, and one-click "Fail & Log Bug".

  • CRUD Access Tab: Configures granular Create (C), Read (R), Update (U), and Delete (D) permissions across Portfolio Level, Project Level, Story/Feature Change/Task Level, and Sub-tasks/Bugs/Test Cases Level.
